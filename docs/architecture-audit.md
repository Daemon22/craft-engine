## 1. System architecture overview

The engine is a **compression + authenticated-encryption library** shipped with a
**CLI**, a small **Next.js HTTP surface**, and a separate **subproject** that
plugs in as a compression strategy.

Observed components:

| Component | Where | Role |
|---|---|---|
| Legacy async library | `src/lib/*` | Primary package export (`.`). Async `Buffer`→`Buffer` API. v1/v2 single-file format, v3 multi-file archive, stream-shaped-input convenience, analytics, HTTP helpers, Prisma singleton, web util. |
| Sync hardened library | `src/lib/craft/*` | Subpath export (`./lib/craft`). Sync API. v1–v3 single-file + **v4 chunked streaming**. Self-verify, fixity sidecars, self-test, `craft doctor`. The CLI is built on this. |
| CLI | `src/lib/craft/cli/index.ts` | `craft` binary. Commands: `nano`, `macro`, `nano-stream`, `macro-stream`, `peek`, `verify`, `watch`, `benchmark`, `checksum`, `doctor`, `version`. |
| HTTP API | `src/app/api/craft/{nano,macro}/route.ts` | Two Next.js API routes wrapping the sync `nano`/`macro`. |
| Codec subproject | `craft-codec/` | `@manya/craft-codec` — standalone order-1 adaptive range coder, consumed as strategy 12. |
| Harnesses | `scripts/*.cjs` + `reports/*.md` | Offline validation/hardening suites producing Markdown reports. |

Two **independent execution paths** exist:

1. **In-memory (gold standard):** `nano()` → `macro()` (v1–v3). Whole file in a
   `Buffer`; `compress7` runs *all* candidate strategies and keeps the smallest;
   AES-256-GCM wraps the result; `nano()` self-verifies in memory before
   returning. Peak RAM ≈ `3 × input size`. (documented in
   `docs/streaming-architecture.md`, `reports/hardening-*.md`)
2. **Streaming (v4):** `nanoStream()` → `macroStream()`. Chunked,
   constant-memory second execution path (peak ≈ `3 × chunkSize`), single
   streaming-native strategy (Zstd default / Brotli), per-chunk AES-GCM. `macroStream`
   is a *universal* reader: it peeks the version byte and delegates v1–v3 to the
   unchanged `macro()`. (documented in `docs/streaming-architecture.md` +
   `docs/chunk-format.md`)

The two paths intentionally produce **different archives** (different
compression, different container) that both restore to bit-identical original
bytes. `docs/streaming-architecture.md` §2 marks `nano()/macro()` as the
"gold standard" and explicitly says the streaming path must never replace it.

## 3. The dual-implementation split (`src/lib` vs `src/lib/craft`)

The most important architectural fact in the repository: **two parallel
implementations of the same idea, neither a wrapper of the other.**

| Aspect | `src/lib/*` (primary export) | `src/lib/craft/*` (subpath) |
|---|---|---|
| API style | async (`Promise`) | sync (blocking) |
| Single-file version | v1/v2 (`CRAFT_VERSION = 2`, `src/lib/types.ts:15`) | v1/v2/**v3** (`CRAFT_VERSION = 3`, `src/lib/craft/types.ts:39`) |
| Max readable single-file | `MAX_VERSION = 2` (`src/lib/macro.ts:26`) | `MAX_VERSION = 3` (`src/lib/craft/macro.ts:36`) |
| Multi-file archive | yes — v3 `archive()/extract()` (`src/lib/archive.ts`) | no |
| Streaming | `src/lib/stream.ts` — stream-*shaped input*, still drains to one Buffer (**not** constant-memory) | `nanoStream/macroStream` — v4 truly chunked, constant-memory |
| Compression strategies | `compress7` (7-fold, strategies 0–7) | `compress7` (12 strategies 0–12, incl. Zstd 10/11 + craft-codec 12) |
| Metadata encryption flag | bit-31 ML flag exists in v3 archive path | bit-31 `METADATA_ENCRYPTED_FLAG` (v3 single-file) |
| Hardening | none of A/C/E/F | self-verify (A), fixity (E), self-test/doctor (C), golden fixture (D) |
| Passphrase minimum | 8 chars (enforced in `src/lib/nano.ts` 〔inferred from craft.test.ts expecting `<8` rejection〕) | 12 chars |
| Web leftovers | `db.ts` (Prisma singleton, excluded from `tsconfig.base.json`), `utils.ts` (`cn()` clsx+tailwind-merge), `http.ts` (`contentDispositionAttachment` used by API routes) | — |
| CLI | not used | **used by the CLI** |

Both modules re-export their own `codec`, `integrity`, `compress7`, `nano`,
`macro`, `peekMetadata`; the names collide but the implementations differ.

`src/lib/craft/README.md` states the intent plainly:

> "This is a separate, sync-API implementation living alongside the package's
> primary export… **If you're deciding which to use: this one has more
> compression strategies and more safety guarantees; the primary export has more
> historical usage.** Consolidating them is an open decision."

The two `v3` values are **different formats**: `src/lib/archive.ts` writes a
multi-file archive at `CRAFT_ARCHIVE_VERSION = 3` (`src/lib/types.ts:18`), while
`src/lib/craft/nano.ts` writes a single-file v3 package with the
`METADATA_ENCRYPTED_FLAG`. Neither reader understands the other's v3
(`src/lib/macro.ts` max 2; `src/lib/craft/macro.ts` reads single-file only).
〔inferred: this is the historical origin of "7-fold" — the legacy selector
tried 7 candidates; the sync one now tries 12.〕

## 4. CRAFT archive format & version lineage

Common container (both implementations): `CRAFT_MAGIC = "CRAFT1"` (6 bytes,
`0x43 52 41 46 54 31`), then a 1-byte version.

| Version | Writer | Reader | Contents |
|---|---|---|---|
| 1 | legacy `nano` (v1) | legacy + craft `macro` | single blob, Brotli-compressed, AES-256-GCM, plaintext metadata |
| 2 | legacy `nano` (current, `CRAFT_VERSION=2`), craft `nano` (v2 mode) | legacy + craft `macro` | single blob, 7-fold/adaptive compression |
| 3 (single-file) | craft `nano` (`CRAFT_VERSION=3`) | craft `macro` only | single blob; `ML` bit31 = `METADATA_ENCRYPTED_FLAG` (`0x80000000`, `src/lib/craft/types.ts:42`) ⇒ metadata section is `META_SALT(16) + META_IV(12) + META_AUTH_TAG(16) + AES-GCM(JSON)` |
| 3 (archive) | legacy `archive()` (`CRAFT_ARCHIVE_VERSION=3`) | legacy `extract()` only | multi-file; `META_JSON` passed as **AAD**; payload = concatenated `NAME_LEN(2)|NAME|DATA_LEN(4)|DATA`, compress7'd then encrypted |
| 4 | `nanoStream()` (`STREAM_VERSION = 4`, `streamCore.ts:51`) | `macroStream()` (universal) | chunked streaming — see §7 and `docs/chunk-format.md` |

Metadata layout (v1–v3 single-file, from `src/lib/craft/nano.ts:114` and the
legacy `src/lib/nano.ts`): `ML` is a 4-byte big-endian uint32; bit 31 means
"metadata encrypted", low 31 bits = section length. When encrypted, the section
is `salt(16)+iv(12)+authTag(16)+ciphertext`. The **metadata JSON is bound as
AAD** to the payload encryption in the archive path
(`src/lib/archive.ts` header comment); in `nano()`, metadata is encrypted
separately with its own PBKDF2 key 〔inferred from the two-salt layout〕.

Version guards: unknown versions are rejected with a descriptive error
(`Unsupported CRAFT version: N. Supported versions: 1-MAX.`) at
`src/lib/craft/macro.ts:117-120` and `src/lib/macro.ts:56-59`. v4 packages are
rejected by `macro()` (max 3) — they *opt into* `macroStream`
(`docs/chunk-format.md` §6).

Backward compatibility is locked by `tests/craft-golden-fixture.test.ts` (see §16).

## 5. Cryptography & key management

All crypto is Node's built-in `node:crypto` (OpenSSL). No third-party crypto
dependency.

- **Key derivation:** PBKDF2-SHA256, **600 000 iterations**, 16-byte random salt
  (`PBKDF2_ITERATIONS = 600_000`, `SALT_LENGTH = 16`). `deriveKey(passphrase,
  salt?)` generates a fresh salt when omitted; AES-256 key (32 B).
- **Encryption:** AES-256-GCM. 12-byte IV, 16-byte auth tag
  (`IV_LENGTH`, `AUTH_TAG_LENGTH`). `encrypt(data, pass, aad?)` returns
  `{encrypted, iv, authTag, salt}`; `decrypt` recomputes the key from the stored
  salt and verifies the tag (throwing on mismatch). Sync + async variants
  (`src/lib/codec.ts`, `src/lib/craft/codec.ts`).
- **Key separation:** v1–v3 single-file uses separate PBKDF2 derivations for
  metadata and payload (distinct salts). v4 derives one **archive data key**
  shared across all chunks plus one metadata key; the shared-key/many-messages
  GCM use is explicitly justified in `docs/streaming-architecture.md` §6
  (fresh random 96-bit nonce per chunk; 2^96 nonce space).
- **Integrity:** SHA-256 of the *original plaintext* stored in metadata
  (`originalChecksum`), verified on restore (`macro`/`macroStream`).
- **Non-determinism:** random salt/IV per operation + `createdAt` in metadata →
  package bytes are unique per run; verified by `harden-world.cjs` phase 6
  (20/20 unique package hashes). This is a security property (ciphertext
  replay/analysis resistance), not a defect.
- **Tamper model:** every byte of the package is guarded — magic, version, ML
  bounds, metadata AAD/tag, payload GCM tag, final SHA-256. The corruption matrix
  is documented in `docs/chunk-format.md` §7 and validated by
  `harden-world.cjs` phase 2 (7/7 scenarios detected, zero silent passes).

## 6. Compression subsystem (`compress7` + craft-codec)

`compress7(data)` (both implementations) runs **every applicable strategy** on
the whole buffer and keeps the smallest; `decompress7` routes purely off a
strategy byte in the compressed payload.

**Legacy `src/lib/compress7.ts`** — 7 strategies (0–7): Brotli, Delta, MTF,
RLE, BPE and their combinations, Brotli plain (〔inferred from
`src/lib/craft/README.md` strategy list and strategy numbering〕).

**Sync `src/lib/craft/compress7.ts`** — 12 strategies (0–12):

- 0–9: Brotli Q11, optionally pre-processed with delta / move-to-front /
  run-length / byte-pair encoding, alone or combined.
- 10–11: Zstd (`zlib.zstd*`, level 22, long window) — requires Node ≥22.15.
- 12: **craft-codec** — `@manya/craft-codec` adaptive order-1 context-modeling
  **carryless range coder** written from scratch (order-1 model + range coder
  in `craft-codec/src/`). O(256)/symbol; **gated to inputs ≤ 4 MB** in
  `compress7` (verified by `craft-subpath.test.ts` — a >4 MB input never picks
  strategy 12). CommonJS subproject, Node ≥18.

Adaptive selection includes an **early-exit**: if Brotli's ratio alone looks
"good enough", later strategies may be skipped — a regression once placed
strategy 12 *after* that exit so it was silently unreachable
(`tests/craft-subpath.test.ts` documents the fix). Selection quality is asserted
by tests (repeat-data ≥95% ratio, craft-codec beats the next-best on order-1
friendly data, `craft-subpath.test.ts:204-269`).

The streaming path **deliberately does not** use `compress7` (whole-file
adaptive selection is incompatible with constant memory); it uses one
streaming-native strategy per archive (`zstd` default level 19, or `brotli`
quality 0–11), stored in metadata as `compressionMode: "stream"` +
`compressionStrategyName` (see `docs/streaming-architecture.md` §4).

## 7. Streaming path (v4) — `nanoStream` / `macroStream` / `streamCore`

Files: `src/lib/craft/streamCore.ts` (constants + shared chunk parser),
`nanoStream.ts`, `macroStream.ts`. Specs: `docs/streaming-architecture.md`,
`docs/chunk-format.md`.

- `STREAM_VERSION = 4`, `DEFAULT_STREAM_CHUNK_SIZE = 1 << 20` (1 MiB).
- **Encode:** `fs.createReadStream(highWaterMark=chunkSize)` → running SHA-256 →
  fixed-size re-chunking → per-chunk compress (independent full codec frame) →
  per-chunk AES-256-GCM (fresh random IV + 16 B tag) → chunk records appended to
  a **temp chunk file on disk** (never all in RAM). When done, encrypt metadata,
  assemble header, stream-copy the temp chunk file behind it, atomic rename
  (read-back verified), delete temp chunk file. Peak ≈ `3 × chunkSize`.
- **Decode:** single pass; one chunk in memory at a time; per-chunk GCM tag +
  per-chunk decompress checked independently; running SHA-256 compared to
  `originalChecksum` **and** restored byte-count vs `originalSize` (catches
  truncation/over-long final chunk). Any chunk failure aborts the restore —
  no partial output is silently emitted.
- **Universal reader:** `macroStream` peeks the version byte; v1/v2/v3 delegates
  to the unchanged `macro()`; only v4 takes the streaming path.
- **`verifyOnly`** mode (used by `craft verify --deep`) decrypts + hashes with
  no output.
- **peek:** `peekStreamMetadata` returns public header fields
  (`ORIGINAL_SIZE`, `CHUNK_COUNT`, `CHUNK_SIZE`, `VERSION`) and redacts
  encrypted metadata to `'[encrypted]'` without a passphrase.
- Chunk record = `COMP_LEN(4) + CHUNK_IV(12) + CHUNK_AUTH_TAG(16) + CHUNK_CIPHERTEXT(COMP_LEN)`;
  32 B overhead per chunk. Header overhead ≈ `83 + len(encrypted metadata)`.
- V4 is atomic-publish only (`output` required or `--force`), matching
  `safeWriteFile` semantics at the API level.

**Naming collision (tech debt):** the legacy `src/lib/stream.ts` also exports
`nanoStream`/`macroStream` but those are *stream-shaped-input wrappers* that
drain into a single Buffer (explicitly documented as **not** constant-memory).
Two different functions with the same name in the two exports.

## 8. CLI architecture

`src/lib/craft/cli/index.ts` (891 lines). Entry: `process.argv.slice(2)`;
`args[0]` = command, `args[1]` = path, `args.slice(2)` = flags parsed by a
hand-rolled `parseArgs()` (`--k v` / `--k` / short `-p`, `-o`, `-f`).

Command dispatch is a **top-level `switch`** (no framework), each command a
`cmd*` function. Command table:

| Command | Behavior | Notable flags |
|---|---|---|
| `nano` | sync `nano()` + strategy table printout + `safeWriteFile` + fixity sidecar | `-p`, `-o`, `--force` |
| `macro` | sync `macro()`; default output = original name next to the `.craft` | `-p`, `-o`, `--force` |
| `nano-stream` | v4 `nanoStream` (also the target of a `--stream` flag route described in docs) | `--chunk-size`, `--strategy`, `--level`, `--quality`, `--no-verify` |
| `macro-stream` | v4 `macroStream`; for v1–v3 delegates to `macro`; derives default output name by peeking the v4 header | `--chunk-size`, `--force` |
| `peek` | version-aware: v4 → `peekStreamMetadata`, else `peekMetadata`; redacts encrypted fields | `-p` optional |
| `verify` | fixity scan of one file or `*.craft` files in a dir; `--deep` = full decrypt+hash (`macroStream(verifyOnly)` for v4, `macro()` for v1–v3); exit 1 on any mismatch | `--deep`, `-p` |
| `watch` | loops `verify` on an interval; logs lines; SIGINT/SIGTERM shutdown | `--interval 30s/5m/1h/1d`, `--log`, `--deep` |
| `benchmark` | runs `compress7` and prints every strategy sorted by size with winner | — |
| `checksum` | SHA-256 of a file | — |
| `doctor` | `selfTest()` — round-trips real fixtures through every strategy family, checks Node/Zstd support | — |
| `version` / `-v` / `--version` | prints version + feature list | — |

Shared helpers:
- `safeWriteFile()` (lines 64–86): refuses overwrite without `--force`; writes
  `.crafttmp-<pid>-<ts>` temp in the same dir; reads back and compares
  byte-for-byte; atomic `renameSync`; best-effort cleanup on failure; exits 1.
- `peekVersionFromFile()` (97–115): reads only 7 header bytes to dispatch
  without loading the file.
- `ratePassphrase()` + `displayStrengthMeter()`: length/mix/unique-char scoring;
  `Invalid` (<12) / `Basic` / `Strong` / `Fortress`.
- `getMime()`: extension table; `formatBytes`, `formatSavingsLabel`
  (unclamped so growth on tiny inputs shows honestly as "X% larger"),
  `savingsBar`.

Exit-code contract: `nano/macro/peek/verify` exit non-zero on any failure;
`verify` exits 1 if `mismatchCount > 0` (safe for cron/scripts).
〔inferred: watch intentionally never exits — it is a long-lived process.〕

## 9. File I/O, atomicity & durability

- **`safeWriteFile`** (CLI): temp-in-same-dir → read-back compare → atomic
  rename. Guarantees: never clobbers without `--force`; a crash mid-write can
  never leave a truncated file at the destination; a filesystem-level write
  error (full disk, permission race) is caught by the read-back check.
- **`nanoStream`/`macroStream`**: same atomic temp+rename pattern; the
  intermediate chunk temp file lives in the OS temp dir and is always
  `unlinkSync`'d in a `finally` (survives SIGKILL/SIGTERM mid-stream). Decode to
  an output path is atomic too (temp+rename); a failed chunk never yields a
  half-written file.
- **Sidecars:** fixity records written through the same `safeWriteFile`.
- **watch logging:** `fs.appendFileSync` per event, best-effort (logging failure
  never crashes the loop).
- **Reading:** v1–v3 `fs.readFileSync` (whole file); v4 streams with
  `createReadStream`; `verify` reads the whole package *only when a sidecar
  exists* (lazy), and uses `macroStream(verifyOnly)` for v4 deep checks so large
  files stay constant-memory.

Measured durability (from committed reports): SIGKILL at 1.5 s mid-compression
left no partial `.craft` and no `.crafttmp`; rerun succeeded
(`harden-world-*.md`, phase 3).

## 10. Fixity sidecar system

`src/lib/craft/fixity.ts` + CLI `verify`/`watch`.

- `computeFixityRecord(buffer)` → `{algorithm, sha256, size, createdAt}` (whole
  package SHA-256 + size). `serializeFixityRecord`/`parseFixityRecord` round-trip
  via JSON; `parseFixityRecord` rejects malformed input.
- `fixitySidecarPath(file)` → `<file>.craft.fixity.json`.
- On `craft nano`, the CLI writes a sidecar next to the package
  (`recordFixitySidecar`, `cli/index.ts:46-50`).
- `craft verify <file|dir>`: for each `.craft` file, if a sidecar exists, verify
  SHA-256 → `OK`/`MISMATCH`; without a sidecar → `UNTRACKED`. `--deep -p` adds a
  full decrypt+checksum check → `DEEP-OK`/`DEEP-FAIL`.
- `craft watch <dir>`: runs the same scan on an interval (`parseDuration`
  supports `ms/s/m/h/d`), never overlapping slow scans (`scanInProgress` guard,
  `cli/index.ts:753-768`), and appends `OK`/`FAIL`/`SCAN-ERROR` lines to
  `--log`. Documented intent: catch bitrot within one interval of happening.
- Known limits (from `src/lib/craft/README.md`): sidecars are **plaintext** and
  reveal package size + creation time; fixity detects and reports only — no
  automated repair.

- **Library:** no logger. Errors are thrown; results carry `integrityVerified`,

- **CLI:** ANSI-colored console output via a tiny `colors` map + `log/success/error/info`

## 13. Error handling model

- **Defense in depth:** every corrupt input must throw — magic, version, ML
  bounds, GCM auth tag, metadata JSON, checksum. Messages are descriptive
  (`Incorrect passphrase.`, `Integrity failure`, `Unsupported CRAFT version`).
- **CLI:** try/catch per command; `process.exit(1)` on any failure. `macro`
  heuristically maps `auth tag`/`Unsupported state` errors to
  "incorrect passphrase." Nothing is silently swallowed except best-effort temp
  cleanup and watch log appends.
- **Boundary validation:** empty input rejected by `nano`/`compress7` by design
  (`Cannot craft empty data`); passphrase minimums (8 legacy / 12 sync); empty
  filename rejected. Verified by `craft.test.ts`/`craft-edge-cases.test.ts` and
  `harden-world.cjs` phase 9 (6/6 invalid inputs throw).
- **No partial success:** a failed restore never leaves a silently-truncated
  output (§7, §9).
- 〔inferred〕 error types are plain `Error` with string messages — no error
  taxonomy/codes; callers sniff `message.includes(...)`. This is a known
  robustness smell (message-coupled branching in `cli/index.ts:322-326`,
  `464-469`).

## 18. Data-flow walkthroughs

**Encode (single-file, v1–v3):**
`file → readFileSync → nano(data, name, mime, pp)` → `compress7` runs strategies
0–12 → pick smallest → build metadata JSON (with `originalChecksum`) →
`deriveKey(metadata)` → encrypt metadata (bit31 flag) → `deriveKey(data)` →
AES-256-GCM encrypt payload → concatenate `MAGIC|VER|ML|metaSection|salt|iv|tag|cipher`
→ **self-verify**: `macro(package)` in memory, compare, throw on mismatch →
return `{buffer, metadata, strategyBenchmarks}`. CLI: `safeWriteFile` + fixity
sidecar.

**Decode:** `readFileSync → macro(buf, pp)` → version guard → parse ML → decrypt
metadata (wrong key ⇒ GCM tag throw) → derive data key → decrypt + `decompress7`
(strategy byte) → recompute SHA-256 vs `originalChecksum` → `{buffer,
integrityVerified, metadata}`. CLI: `safeWriteFile` to original name/`-o`.

**Encode (v4):** `createReadStream` → hashing + re-chunk → per chunk:
`compress (zstd|brotli frame)` → `AES-GCM` (shared key, fresh IV) → append
`COMP_LEN|IV|TAG|CT` to temp chunk file → finalize metadata → header + streamed
chunk file → atomic temp+rename. `macroStream`: `peekVersion` → header parse →
per chunk decrypt+decompress+hash → final SHA/size compare.

**Verify:** `verify <path>` → for each `.craft`: `peekVersionFromFile`; if
sidecar: read package + `parseFixityRecord` + `verifyFixityRecord` → OK/MISMATCH;
if `--deep`: `macroStream(verifyOnly)` (v4) or `macro` (v1–v3) →
DEEP-OK/DEEP-FAIL. `watch` repeats on a timer with overlap guard + file log.

**HTTP:** `POST /api/craft/nano` (multipart, `-p`, 100 MB cap) → sync `nano` →
`.craft` bytes + disposition header; `POST /api/craft/macro` → sync `macro` →
restored bytes + disposition header (RFC 5987 filename).

## 20. Extension points, strengths & tech debt

### Extension points (as designed)

1. **New compression strategies** slot into `compress7` (single-file) and the
   v4 strategy selector (streaming). craft-codec (strategy 12) is the working
   example of a self-contained plugin.
2. **Format versioning** is explicit: bump version byte, keep
   `MAX_VERSION` readers, add golden fixture. v4 shows the pattern (new writer,
   universal reader).
3. **`selfTest()`** enumerates strategy families — a machine-readable place to
   extend environment checks.
4. **Fixity record** format (`{algorithm, sha256, size, createdAt}`) is simple
   and extendable.
5. **`contentDispositionAttachment`** is a reusable, hardened HTTP util.

### Strengths (observed)

- **Lossless, authenticated, corruption-detecting:** double integrity (GCM tag
  + SHA-256 + size), zero silent passes across 7 tamper scenarios.
- **Atomic, non-destructive writes** everywhere (`safeWriteFile` pattern
  duplicated at API level in v4).
- **Self-verification on write** — `nano()` proves the package round-trips
  before it ever hits disk.
- **Backward compatibility locked** by a golden fixture and v1–v3 readers;
  v4 explicitly opts into a new reader rather than breaking the old one.
- **Security posture:** 600k PBKDF2, separate metadata/data keys, per-chunk
  nonces, metadata privacy (encrypted by default, redacted peek).
- **Exhaustive validation story:** 10 test suites + 2 offline harnesses + doctor,
  all cross-checking independent of the engine's own assertions.
- **Honest failure presentation:** unclamped savings labels, exit codes for
  scripts, no partial outputs.

### Tech debt / risks (observed)

1. **Two parallel implementations** of the same domain with divergent formats
   (v3 single-file vs v3 archive; 12 vs 7 strategies; async vs sync; 8 vs 12 char
   minimums) and **colliding names** (`nanoStream`/`macroStream` mean different
   things in `.` vs `./lib/craft`). `src/lib/craft/README.md` itself flags
   consolidation as open.
2. **`bin/craft` is dead** — declared but the file doesn't exist; the CLI only
   runs via the deep `dist` path.
3. **`lint` is broken** (no `eslint.config.js`); `typecheck`/`build:lib` pass.
4. **Missing referenced artifacts:** `README.md`, `LICENSE`, `CRAFT_AUDIT_NOTES.md`,
   `deploy/`, Prisma schema (while `db:*`/`prisma` deps and `db.ts` exist).
5. **Dependency bloat** for a library: the engine core needs only `node:` +
   `craft-codec`, but the published package pulls the full Next/React/Prisma
   tree (and `bun` in `start`).
6. **Message-string error sniffing** in the CLI (`err.message.includes(...)`) —
   brittle coupling to copy.
7. **No CLI unit tests, no route tests, no coverage of legacy
   `archive/analytics/stream/http`** — the untested surface is exactly the
   diverging half.
8. **Flaky-by-threshold perf suite** on slow CPUs (8 recorded timeout failures,
   retried ×2) — thresholds are machine-dependent.
9. **`tsconfig.base` excludes `src/lib/db.ts`** — the Prisma singleton is
   excluded from builds; `db:*` scripts have nothing to migrate.
10. **Coverage config vs reality:** thresholds configured but no coverage run in
    the committed logs; `src/lib/**` include list would also count the divergent
    legacy modules.
